# 财报研究助手 V1.2 使用与演示路径

工程候选，2026-11-02。最终通过/失败/跳过和真实模型证据以 tests.md / release-notes.md 为准；本说明不是验收通过声明。

## 开始与连续追问

首次使用全新 runtime，先在首页或“企业与资料”建立企业、上传带文本层的年报，核对企业/报告年度/期间/会计口径，等待来源身份核验及解析、索引就绪。资料没有达到可选择状态时，不会出现在会话可选列表；新目录不自动带入测试年报或历史财务确认。来源准备可参考仓库 README 的“开始一次研究”。

然后打开 `/conversations`，明确选择1–4份已核验年报，再点击创建会话。创建不会自动发送草稿。会话顶部显示冻结范围；换资料需明确新建会话。旧 `/research?mode=qa` 仍可作为单次原文核验/历史问答入口。

可按实际已选企业和年度输入，例如“请引用年报原文说明美的集团2025年的营业收入，不计算同比。”，接着问“同比变化呢？”，再问“经营现金流也这样吗？”。系统展示本轮解析的企业、财务年度与指标；有多个主体、未知主体或年份不清时先澄清。报告年度和财务数值年度分别显示。

原文回复是已核验引用的摘录，保持披露原单位/原文；引用可回到真实PDF物理页。已确认事实与比较结果来自服务器事实/既有Decimal公式。缺少确认事实、尚未明确选择披露版本或来源失效时，不从原文心算同比。点“选择已确认财务事实”明确选择本会话来源中的有效版本；缺少数据时前往原有核对流程，接受、保存和继续仍分别由用户明确触发。

本版优先连续证据阅读和同一企业的期间比较，自由解释关闭。原有经营研究仍保留其跨企业等流程。引用身份核验不等于真人已审核所有财务语义。

## 历史、未知与并发

刷新/重新打开/读取历史/查询操作均不再次运行模型。网络失败后保留本次操作，使用“查询本次操作状态”，不要另开同一提交来猜测结果。GET暂时查不到也不证明原请求未执行。服务重启后未完成轮次标记中断，用户下一次明确发送才执行新的轮次。

两标签并发由数据库拒绝第二个活动轮次。明确未登记的busy拒绝保留草稿，先只读刷新；原轮次终态查明后，才由用户再次点击发送。供应商可能已处理但响应丢失，本应用不自动发第二次，不承诺供应商端计费exactly-once。

## 偏好记忆

输入“以后研究先关注现金流”只产生待保存候选；点击独立“保存偏好”才保存。也可打开“我的研究偏好”明确选择分析侧重、展示单位或研究习惯。保存/编辑/删除均有独立回执；版本冲突需重新读取后人工决定，不自动覆盖。

当前仅支持有限选项。偏好作为后续请求的有界背景数据，不能决定来源授权、确认财务值或改变计算单位。删除后后续请求不再从Memory注入该偏好；旧已提交消息、供应商已收到的请求及备份可能仍保留原内容。删除会话与删除偏好是独立动作；删除会话不删除PDF、旧ResearchRun或已确认事实。

## 本地运行

所有写入仅供当前demo单人本地空间。服务绑定回环地址；没有登录/多租户隔离承诺，不公开暴露带私人记录的写接口。

实际模型运行要求已安装项目依赖及BGE/Milvus资源，模型配置文件路径须替换为本机真实路径，使用新的绝对runtime目录（不要指向正式/冻结数据）。

```bash
# 后端；MODEL_ENV_FILE须先设为实际模型配置文件的绝对路径。
FINDOC_RUNTIME_ROOT=/absolute/path/to/new-isolated-runtime \
  python -m uvicorn app.api.runtime_factory:create_isolated_runtime_app_from_env \
  --factory --env-file "$MODEL_ENV_FILE" --host 127.0.0.1 --port 18090

# 前端，Node24，仓库frontend目录下。
FINDOC_API_ORIGIN=http://127.0.0.1:18090 npm run dev -- --host 127.0.0.1 --port 14290
```

前端访问 `http://127.0.0.1:14290/conversations`。模型请求会把必要问题、证据和允许的上下文发送到已配置供应商；本地Memory不使用第三方记忆服务。测试替身运行器与真实运行入口分开，具体命令见 validation-a4-preparation.md；替身不证明真实模型准确率。
