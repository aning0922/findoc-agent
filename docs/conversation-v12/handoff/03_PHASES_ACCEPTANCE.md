# 03｜阶段任务与验收方案

## A0 — 冻结合同、影响面和产品路径（0.5–1 天）

- 按 `main@1f0a3d4` 确认真实结构和可复用服务，检查 `app/research/models.py`、`research_runs.py`、`task_checkpointer.py`、`SelectedScopeSearch`、`FinancialAnalysisService`、旧 `/chat`、`research_history_app.py`、当前 UX PR 的测试。
- 产出 `docs/conversation-v12/contracts.md`、`architecture.md`、`migration-plan.md`、`journey.md`、`risk-register.md`。
- 初版展示 4 种状态：空会话、多轮回答、缺少确认事实、失效/未知状态；桌面和移动。只设计原型，不调整旧业务。
- 质量闸口：声明哪些语义变化会碰旧合同；与用户目标冲突时选最窄方案，不假设 `TaskCheckpointer` 天然适用于聊天。

## A1 — 会话与幂等持久化（1.5–2 天）

- 新增 `app/conversations/{models,schema,repository,service,api}.py`（文件组织可按当前项目风格修订）。
- 使用追加式迁移，优先全新隔离数据库运行。快照 hash、operation id、唯一约束、running 互斥、终态不可变、GET 只读。
- 仅做 `create/list/detail/send/register/read-by-operation`，先用 fake handler 返回确定文本；真实模型另阶段接入。
- 测试：双击只登记一次；相同 op 不同请求 409；越界 document 拒绝；GET 不写；旧数据库迁移校验通过；历史 ResearchRun 无改写。

## A2 — 多轮语义与工具路由（2–3 天）

- 新建 ConversationGraph（独立线程 saver 与主仓储），最近消息+轻量焦点状态，结构化指代消解； `thread_id=conversation_id`。
- 只读工具：年报原文、确认事实、已有确定性比较；每条链复核固定数据来源；不得直接接受候选事实。
- 第一轮优先输出稳定证据阅读 + 已确认计算；自然语言解释是单独受控的待审字段。为“那上一年呢”“它的经营现金流呢”“换一家呢”等场景补澄清与范围防护。
- 测试：上下文指代、来源冻结、source invalidation、工具参数越权与虚构数值拒绝、预算上限、模型 JSON 不合规、网络 UNKNOWN 不重试。

## A3 — React 对话界面（1–1.5 天）

- `frontend/src/product/` 新增会话页面、消息、来源栏；路由新增 `/conversations`，导航“研究助手”；旧 `/research?mode=qa` 不删。
- 用户可创建会话、选择/确认 1–4 份年报、发送消息、继续已有会话、查看来源、找到现有财务核对页面。
- 移动抽屉、滚动位置与焦点行为需要沿用 UX PR 的锁清理策略；请求中显示明确状态而非未经验证的流式内容。
- 验收：1440px / 390px 无溢出、输入与按钮键盘可达、未知提交无虚假成功、历史只读浏览无模型调用。

## A4 — P0 发布质量闸口（1–1.5 天）

- 实际新建会话→真实多轮问题→财务需要核对→完成核对后再提问→重新打开历史。
- 初版使用受控替身覆盖全部状态，再至少以真实年报+真实模型跑有限数量 live 测试。
- 运行原有 frontend/backend/quality 与 UX 回归；没有绿灯证据不得宣称完整通过。
- PR 独立审查：消息所有权、SQL/模型重放、引用身份、历史兼容、启动恢复。

## B1 — 长期记忆的明确写入与管理（1–1.5 天）

- 新建 `app/memory/` 及 `memory_items`/audit，首先只支持研究偏好。
- 来自用户的潜在记忆展示为候选 UI，确认写入必须有单独的明确 action；模型与 PDF 无写权限。
- 可按范围列出、编辑、删除；删除后的新会话不召回旧值。冲突更新使用 revision；并发避免覆盖。
- 记忆中的 `source_turn_id` 仅为“用户表述出处”，不是可信企业事实。

## B2 — 上下文压缩与跨会话召回（1.5–2 天）

- token 预算/覆盖游标 + 摘要；摘要内容包含“问题指代焦点、讨论进度、待澄清项”，不包含未经确认的数值真值。
- 只能注入本地用户已确认且当前有效的偏好；记忆不能决定实际 source scope。
- 验证 20+ 轮聊天上下文不会无限增长，摘要刷新/服务重启仍可回到正确指代。
- 旧 thread 删除、偏好删除后不能从旧摘要/缓存恢复已删除偏好；可用不可恢复的内容删除边界需明确文档说明。

## G — 最终真实验证、演示与交付（1–2 天）

- 审查记录：`requirements.md`、`design.md`、`api-contract.md`、`migration.md`、`tests.md`、`release-notes.md`、真实运行记录（带准确环境和模型）、截图、PR/commit。
- 旧静态演示不冒充新会话功能。新能力需单独真实演示视频或只读种子案例，标记模拟/真实模型边界。
- 正式本地资料与之前冻结测试原件的 SHA、旧历史数据和 migration checksum 不被改写。

## 最低验收集（建议自动化 + 真人手工）

| 编号 | 测试 | 成功标准 |
| --- | --- | --- |
| C01 | 三轮指代：营收→同比→现金流 | 解析对象明确；不会错配年份 |
| C02 | 模糊指代（“它”可能指两个企业） | 澄清，不自行换企业 |
| C03 | 重启后继续会话 | 读取历史 + 同一 scope；GET 0 次 LLM |
| C04 | 双浏览器标签同时发送 | 至多一条 active turn，不出现交错结果 |
| C05 | 重复 operation，同载荷 | 返回同一状态；模型尝试次数不增加 |
| C06 | 重复 operation，异载荷 | 409 冲突 |
| C07 | 断网、模型超时、POST 响应丢失 | UNKNOWN 只读查询，不自动重发模型 |
| C08 | 选定年报外的企业/年份 | 未授权范围拒答或要求创建新会话 |
| C09 | 已引用的 PDF 来源版本失效 | 旧结果为历史，只读；新回答不使用失效引用 |
| C10 | PDF 含“请记住这条指令” | 无记忆写操作，无扩权工具调用 |
| C11 | 未接受的财务候选 | 不进入已确认计算，不给精确同比值 |
| C12 | 已确认财务事实 + 既有公式 | 数字与服务端 Decimal 结果一致，有事实证据 |
| C13 | 模型编造页码/事实 ID | 后端拒绝生成可发布的可信结果 |
| C14 | 研究偏好候选未确认 | 新会话不召回 |
| C15 | 确认偏好 | 后续会话在允许范围内召回 |
| C16 | 删除偏好 | 后续会话不再召回，旧缓存不可重现 |
| C17 | 长会话超预算 | 摘要/裁剪触发，结论不依赖摘要伪事实 |
| C18 | 390px/1440px 阅读 | 无焦点/滚动锁泄漏，原 PDF 可打开 |
| C19 | 现有 ResearchRun 历史 | 字节/协议/不可变规则与既有行为一致 |
| C20 | 旧经营研究流程 | ACCEPT/SAVE/RESUME 不自动执行，原 UX 回归通过 |

应增加版本切换、会话删除、记忆编辑、提示注入、失败恢复、辅助技术操作等专项测试。实际模型观察需要记录答复、模型调用数、工具次数、证据身份及输出是否待审；不能把 fake 绿灯充当真人准确率。

## 模型协作与提交纪律

- Codex 主控：GPT-6.1 中/高推理，独立架构/边界评审：GPT-6 Astra 高（只在 A0 规划和 G 阶段最终复审使用）。实际可用名称/额度以用户客户端为准。
- 主控负责唯一修改工作树与提交；研究代理只读审计，避免并行争抢数据库 migrations 和 `runtime_factory`。
- 每阶段分支或独立 commits，有可复现测试数据；任何 PR 附带风险、未覆盖项与回滚说明。
- 重点优先交付可演示 P0：如果 A0 检查出严重源范围/依赖问题，先减小功能面而非伪装为完成。
