# 01｜业务能力与 UX

## 1. 产品用户故事

**S1 连续追问（P0）**
用户选中 A 公司 2024/2025 年报并提问“2025 年营业收入是多少？”→ 再问“同比变化呢？”→ 再问“现金流也这样吗？”。系统应保持企业、年、指标的局部上下文；展示具体解析出来的指代，并在不明确时问澄清，不得悄悄换来源。

**S2 工具与可信财务（P0）**
- 原文事实：使用已选择、已核验年报的原文检索，展示原文、报告年份、物理页码、引用及状态。
- 财务变化：优先用 `local_operator` 已确认且当前有效的财务事实与既有确定性分析服务。缺失时提示“尚无可用于正式计算的已确认事实”，链接到当前来源的核对流程，不能自动接受、保存或凭文本推算。
- 经营解释：允许受控自然语言总结已检索证据，但**证据元数据由服务端产生，模型解释须标明待人工语义审核**。不满足引用或来源资格时拒答；提示用户查看已保存原文。

**S3 会话持久化（P0）**
退出页面与重启服务后，历史会话与消息不丢失；GET 只读，绝不重新调用模型、重新计算或写财务事实。选择不同年报应显式“创建新会话”，保持旧会话来源冻结，不在用户不知情时改变历史范围。

**S4 长期偏好（P1）**
用户说“以后研究先关注现金流”，系统建议一条“研究偏好”候选，但不自动存储；用户点击“保存偏好”后，可在新会话中召回。用户可查看、修改、删除，删除后不再注入后续 Prompt。

**S5 真实失败（P0/P1）**
供应商超时、断网、结果 UNKNOWN、源文件版本改变、记忆存储失败、两个浏览器标签同时提问均有可靠提示与安全恢复；查询状态不能重发 POST。模型回复中的“记住我”不能直接进入存储。

## 2. 页面信息架构

主导航原则：不为每一种工具开新顶级页面。

- 建议将原导航“年报问答”更名“研究助手”，点击进入新的 `/conversations` 页面；旧 `/research?mode=qa` 保留为“单次原文核验/历史问答”，所有原有深链有效。
- 对话桌面布局：左栏会话列表（新建/继续/搜索），中间消息流与固定输入区，右栏按需展开“当前来源及引用”，不是默认永久三栏挤压正文。
- 移动布局：会话抽屉与来源抽屉，消息流单列，输入区随可视区域布局；抽屉关闭清理 focus/scroll lock。
- 对话顶部：当前企业、当前冻结年报范围、状态、开始新会话入口。不在聊天输入中暗改研究范围。
- 消息区：用户消息、助手结论/原文、工具进展（默认折叠）、证据卡（报告年份/页码）、“已确认数据”与“AI 分析待审”明确区分。
- 底部建议动作：继续提问、查看原 PDF、去核对财务事实、查看原任务或完整报告。每个动作链接须从服务端身份构建且再核验。
- 记忆管理：侧栏/设置“我的研究偏好”，条目可读、可改、可删。拒绝空白、重复或模糊的自动记忆。

## 3. 两个相似但不同的输出模式

**证据阅读（保守模式）**：调用已有 `RAGService.answer_selected` 并复用 `ResearchRun`，保持原文摘录不可变；自然语言的上下文解析在进入当前单次检索前完成。

**研究助手（受控解释模式）**：使用严格的结果结构包含 `answer_text`、`evidence_refs`、`verified_financial_fact_refs`、`interpretation_status`；将来源资料和模型草稿分开保留。显示“引用已核验”不代表已核实 AI 解释的所有因果含义。缺少充分证据不能输出未经支撑的定量结论。

P0 先让连续追问以证据模式稳定工作，财务计算调用已确认服务；解释模式在对话链安全闸口完成后实现，防止大规模破坏旧合同。

## 4. 交互设计原则

- 首次打开给出 2–3 个可点击示例问题；先选年报，再开始会话。
- 避免在普通页面直接显示 revision/SHA/UUID，折叠为“查看技术详情”。
- 一次回复只有一个主要下一步；对话恢复不写，只有用户点击发送才写入新 Turn。
- 结果未知不显示“已成功”，旧数据失效立即标注或撤下当前有效声明。
- 所有未确认财务候选均明确标“待核对”，和经过入库的已确认事实视觉区分。
