# M1 discovery UI handoff

Base `132fd7d8a8efd171fef4136c4ccdc1fd7da725ea`. Named export `CompanyDiscoveryPanel` in `frontend/src/product/cplus/sources/CompanyDiscoveryPanel.tsx`; props `{companies?: Company[], onImported?: (companyId: string, documentId: string) => void}`. Root mounts it in the existing homepage/company directory and owns navigation, controller wiring and cleanup boundaries. No unrelated frontend or backend files changed.

Explicit actions call same-origin POST `/api/cplus/discovery/searches` with companies `{mode:'companies',query}` or announcements `{mode:'announcements',security_id,report_year,kind}`. Candidate list displays code, market and supported state; official_name null is displayed as awaiting cover validation. A/H candidates are keyed by `security_id`, never orgId. Announcement display uses `title_raw`, kind, language, revision_kind; only chosen matching-security Chinese annual_fulltext is importable. `partial` is displayed. UI will not accept raw URL and official-page links require HTTPS `www.cninfo.com.cn`; fixed fallback is official site/manual upload.

Import POST `/api/cplus/discovery/imports` sends `{operation_id,candidate_id,candidate_digest,company_id,create_company,confirmed:true}`. If supplied `companies` contains exactly one matching code+exchange, that company_id is used and create_company=false; no match requests null + true after clear “导入并建立企业资料” button. More than one match blocks import. Actual binder remains responsible for final company/cover/market verification. This component does not invent or submit a legal name.

Each explicit write creates and stores UUID before sending. Unknown/non-2xx/malformed response keeps `{id,kind,mode}` in sessionStorage and blocks further writes; “查询原操作” does GET `/searches/{id}` or `/imports/{id}` only. A server `failed` terminal state clears it; 404/unknown does not. After reload, completed search results are applied; recovered announcements restore the server-returned security identity. Storage errors fail closed. User should consult operator on unrecoverable 404, not automatically submit a new operation.

Completed import saves only `{companyId,documentId,state}` and does not equate receipt's document_state with READY. The component polls existing GET `/api/documents/{id}` 2.5s with actual `document_id/status/safe_error_message`, stops on ready/failed, and checks GET `/metadata` company_id on ready. A stored READY is rechecked on mount; the “查看已就绪资料” action rechecks document READY and metadata before invoking onImported. Callback is never invoked by import or polling alone. queued/parsing/indexing/failed are shown separately. Polling and read-only recovery never call the provider or trigger downloads.

Root must add **both exact keys** `findoc:cplus-discovery-operation` and `findoc:cplus-discovery-import` to the generation-bound demo housekeeping allowlist, preserving them for same verified generation and clearing them on reset/takeover. Do not treat sessionStorage values as authority; server validates all identities.
