# 系统架构

FinDoc Agent 由 React 工作台与 FastAPI 服务组成，以中文年报为输入。检索、财务确认、确定性计算和模型解释使用独立合同；界面中的结果可以回到对应文档版本和物理页。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `app/companies` | 企业目录、报告元数据和数据库迁移。 |
| `app/documents` | 上传、处理状态、原文件存储、来源版本、证据读取与纠错。 |
| `app/rag` | 解析、分块、bge-m3 向量化、Milvus Lite 检索、证据上下文与引用校验。 |
| `app/agent` | 工具注册与执行、参数和范围验证、财务候选、人工确认和 Decimal 分析。 |
| `app/research` | 单文档及多文档研究结果、模板、任务状态和历史读取。 |
| `app/reports` | 从保存研究构建报告，维护不可变版本，核验资格并导出 Markdown。 |
| `app/api` | 严格请求模型、HTTP 路由、服务装配与错误映射。 |
| `frontend/src` | 研究导航、原文阅读、财务核对、问答、任务和报告界面。 |

## Agent 如何执行

模型可在受控循环中申请工具，应用负责校验工具名称、JSON 参数、文档范围和调用预算。工具 schema 不赋予模型修改服务端工作空间或授权结论的权力。工具执行结果与模型文本分别保存。

经营研究采用有限模板和 LangGraph 工作流。缺少已确认财务事实时，任务进入人工等待；用户核对、明确接受并独立保存后，再显式继续。历史 GET 和页面刷新读取已保存状态，不自动重跑模型。当前方案是受约束的研究执行器，不声明任意自主规划能力。

## 数据与证据

PDF 解析保留物理页、表格和可用的布局坐标。来源版本绑定文档身份、文件摘要、处理尝试及解析版本。引用、财务事实和报告关联该来源；来源纠错或确认撤销会影响当前可用资格，历史快照保留用于审计。

财务候选支持营业收入、归母净利润、经营活动现金流量净额。原值与原单位独立保存，确认后统一规范为人民币元；服务端以 Decimal 和固定公式计算差额、同比或同期相对差异。零基数、负基数、缺失期间及口径冲突有明确状态。

问答使用显式选定报告范围进行检索，经上下文构造、生成和引用验证输出回答、拒答或系统错误。模型解释与财务事实区分展示，引用有效不自动等于因果归因已通过人工审核。

## 运行边界

SQLite 保存业务记录、财务事实、研究任务和报告版本；本地文件保存 PDF，Milvus Lite 保存索引。默认是本地单人工作空间。没有把本机隔离等同于多人权限系统，也没有通过静态演示对外开放写操作或模型调用。

报告读取复用不可变保存版本；导出重新检查来源与事实资格，但不重新执行研究或财务计算。独立静态演示只展示已筛选的历史内容，不具备当前业务资格。
