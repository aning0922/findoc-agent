# 三条面试演示脚本（执行草案，非验收报告）

当前演示目录仅美的集团（000333）与格力电器（000651）2024/2025四份年报。日期、更正状态未知时如实展示，不称全市场实时查询。以下步骤需在已启动的当前代服务执行；seed中资料是否完整以当前列表为准，不能以目录四份推断全入库。示例问题不包含未经核准的金额。真实模型调用统一由root的预算proxy计费，本轮全局5元；没有预算/配置时保留未执行，不用fake充当真实模型结果。

## 1. 登录、官方资料与快速原文（约4分钟）

1. 打开演示首页，在“欢迎体验 FinDoc”输入本人获授权的账号和密码，点“进入演示”。若出现恢复中，等待领取完成；若空间被占用，不擅自接管。首页只说明当前实际计数与资料范围，不承诺未验证功能。
2. 在资料管理中选格力企业，官方目录输入格力/000651和2025，点“查询目录”；展示“已验证演示目录”、未知发布日期/更正状态和“查看官方来源”。如尚未导入，点“明确导入此年报”，等真实状态READY；断线只查原操作。若已存在，使用该版本，不重复下载。此导入不产生财务确认。
3. 进入 `/conversations`。点“选择年报”，勾选格力2025，点“创建会话”。在“研究问题”输入“摘录关于经营现金流变化的原文，并给物理页”，点“发送”。查看实际回答与引用，点“查看原 PDF [编号]”，对照物理页与摘录。无证据/无模型时展示失败或限制，不现场补造答案。
4. 关闭阅读层，点“只读刷新会话”，证明历史读取不新生成模型答案。说明“已保存原文摘录”不等于财务签核。保存本轮operation/turn/source_revision、实际调用和时延，记录失败同样有效。

讲解句：系统将选定来源冻结在会话中；答案引用要回到原文核查。真实程序核验与人工语义审读是不同证据。

## 2. OCR、候选指标与本人核对（约5分钟）

1. 在已挂载的文档解析质量区域打开“查看解析质量”，选择本代实际存在的OCR产物。已有样本是美的2025物理第9页栅格化生成的单页扫描派生PDF；它不是原生扫描披露年报，派生产物物理页1对应原文第9页，需明确说明。
2. 阅读真实 engine/处理状态、OCR页数、限制，在页视图点“查看原页大图”，对照“候选转录 · 未核对”和“版面候选 · 需人工核对”。没有产物时，仅在明确需要重新解析时点“明确开始新解析”；partial/failed不可讲成完整成功。不以OCR完成授予封面身份或财务资格。
3. 在扩展财务视图阅读总资产/总负债候选及来源。若没有已核准事实，图表缺口应保留，不补零。跨年数据需看实际财务日期，2025报告比较列不是2025事实。扩展候选路径与旧固定三指标流程分开。
4. 如要演示旧真人核对，进入 `/research?mode=operating`，由本人选择合法双年/双企业任务及来源。旧流程整组固定六项（两侧各营业收入、归母净利润、经营现金流），不是把扩展候选塞进旧流程。本人逐项对照PDF、年度、单位、口径和来源后，在“人工核对确认”中勾选“我已逐项核对原 PDF，并明确接受本次审阅内容”，再点“我已核对并接受”。这一步要求本人操作，不能由Agent代点。
5. 接受只保存核对记录；接下来本人再执行独立“保存数据”步骤，并核验接受凭证/保存时间。任务继续是另一项明确操作，不与接受/保存合并。未完成这些真人步骤就结束在“候选未核对”，在记录中写human_pending，禁止宣称计算资格已通过。

讲解句：OCR提供候选转录，程序管理来源和状态，金融事实的独立接受、保存和任务继续仍由本人逐步确认。

## 3. 单/多研究、版本报告与跨会话记忆（约6分钟）

前置：同一代合法会话已冻结格力2025（或明确选择四份）；选择事实集合不变。新Agent UI挂载尚可能变化，以下使用真实已实现API作为稳定演示入口，不假设存在“启动多Agent”等按钮。请求通过root提供的同源受控调试工具/当前已登录会话发送，不在脚本放凭证；每次新mutation使用新operation_id，UNKNOWN仅GET查证。

1. 问题固定“现金流风险还有哪些待核查？”分别 POST `/api/research/intent`，body为 `{operation_id,conversation_id,text,requested_mode:'synthesis'}` 和另一份requested_mode:'deep'。这会产生模型预算，必须由root统一代理执行。保存各自真实intent_id；不能从历史旧Task捏造新job。
2. 各自 POST `/api/synthesis/plans {operation_id,intent_id}`。读取返回的计划和scope，确认角色/范围与budget；若未拿到合法plan就停止并记录失败。批准后分别 POST `/api/synthesis/jobs` 与 `/api/deep-research/jobs`，只提交 `{operation_id,approved_plan_id,approved_plan_revision,approved_plan_sha256,confirmed:true}`。计划ID/revision/hash必须来自对应服务器计划，不手填事实授权。
3. GET相应jobs/{id}与events?after_seq=0，查看已持久公开事件而非私有思维。等实际completed；UNKNOWN/failed/interrupted保留。并列记录真实calls/tools/findings、来源覆盖、费用和时延，不能预设多Agent更好。GET不新发模型请求，重读前后预算账本应一致。
4. 对一个真实completed job，POST `/api/showcase-reports/drafts {operation_id,job_id}`，再 POST `/api/showcase-reports {operation_id,draft_id,title,notes}`，不传findings/金额。报告库挂载后打开该版本；若未挂载则GET报告revision及其`/print`同源路由。检查来源状态、四类发现、AI待审/未覆盖标签，使用“打开打印页 / 保存 PDF”并在浏览器实际保存。只有文件真实产生并检查后才能讲“已导出”，点击链接不算完成。离线引用页链接需要服务/登录权限。
5. 在已挂载的“研究记忆与偏好”中新增“现金流待复核事项”，勾选明确确认并“保存记忆”。另建同公司新会话（不要传没有source_turn_ids的conversation引用），搜索“上次现金流还有哪些问题”。真实BGE召回和新研究使用分别留证；笔记不是财务事实。随后二次确认删除，未来搜索和新研究不应再用它，历史已发布结果仍只读保留。无结果就直接展示无结果。

可复跑证据：同scope两臂job/plan IDs、事件序列、budget账本、版本报告ID/revision、真实PDF路径、记忆operation与删除generation。mock演示记录单列fake，不能补成真实模型或真人财务通过率。
