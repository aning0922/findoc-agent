01 / WHAT THIS PROJECT SHOWS

把结果接回证据。

三项能力，从业务问题落实到可验证的工程边界。

01

财务变化可核对

先核对和接受事实，再独立保存。Decimal 计算差额与同比，原值、单位与比较方向一并保留。

案例：收入 +12.11%，经营现金流 −11.84%。

阅读财务变化 →
02

回答可回原表

限定年报版本检索，将答案绑定到原值、年度列和 PDF 物理页。出处核验与人工语义审阅分别记录。

案例：A10 营业收入 456,451,731 千元。

核对 A10 原表证据 →
03

报告可追版本

冻结研究结果，追加报告 v1 / v2。明确展示字段差异，按指定版本下载保存时的 Markdown 原字节。

案例：标题改变，新增一条用户结论；编辑仍待审。

02 / A THREE-MINUTE WALKTHROUGH

沿着一份研究，走完三分钟。

时间是讲解预算，未作为陌生用户完成时间实测。

  1. 00:00—00:45

    看结果：两年原值与三项变化

    辨认年度、千元单位、比较方向和精确差额。金额计算来自确定性结果。

  2. 00:45—01:30

    看证据：A10 原表与年度列

    展开完整表格；区分原生 pending 与仅适用该历史 Run 的 D28 外部意见。

  3. 01:30—02:15

    看报告：摘要与待审编辑

    财务结果、模型原句、人工意见和用户结论分别保留。

  4. 02:15—03:00

    看版本：对照变化，再下载 v1

    核对标题和结论的变化，再读取指定 v1 原件。历史原件中的 API / 相对引用需要原应用环境。

03 / SYSTEM & OWNERSHIP

把人工决定留在流程里。

以下是正式单机工作台的技术架构；当前作品页仅承载静态文件。

  1. 交互与决策React / TypeScript

    核对 → 接受 → 独立保存 → 明确继续

  2. 服务与流程FastAPI / LangGraph

    固定模板编排、人工等待与持久继续

  3. 检索与计算BGE-M3 / Decimal

    Milvus Lite 限定来源检索；有限 Function Calling

  4. 状态与交付SQLite / 版本报告

    持久状态、冻结研究与指定 revision 下载

本人负责

业务范围与产品决策、单企 / 双企比较方向、工程合同和验收标准；亲自核对原 PDF 与十二项财务事实，决定接受、独立保存和三次明确继续；组织演示与证据交付。

与 Codex 协作设计、实现和验证。D30 报告 v2 标题示例由 Codex 执行，仍待审，不归为本人语义批准。

固定模板与有限工具调用不等于自主规划 Agent。未实现混合检索 / rerank，当前为单机作品，不宣称多人生产平台或已验证的逐指标经营因果分析。
